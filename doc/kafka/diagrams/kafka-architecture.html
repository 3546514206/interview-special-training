Kafka 架构与工作原理

Producer → Broker（Leader / Follower + ISR）→ Consumer Group；KRaft 管元数据，分区内顺序追加、按 offset 消费

元数据与选举

  • • KRaft Controller Quorum，3 个投票节点
  • • 元数据写入内部日志，不再依赖 ZooKeeper
  • • Controller 故障时由 quorum 重新选主
  • • Leader 副本失效时，从 ISR 中选新 Leader

复制与可靠性

  • • Leader 收写，Follower 持续 fetch 同步
  • • ISR = 跟得上 Leader 的副本集合
  • • acks=all + min.insync.replicas 才能不丢
  • • HW = min(ISR 的 LEO)，消费者只能读到 HW

消费与位移

  • • 拉模型：消费者按自身速度 poll()
  • • 一个分区同时只分给组内一个消费者
  • • offset 提交到 __consumer_offsets
  • • 成员变化触发 Rebalance，分区重新分配

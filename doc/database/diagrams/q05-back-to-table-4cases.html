    EXPLAIN 关键列速记
    
      
    
      
      
        
    • · type: 走什么路径 (ALL < index < range < ref < const)
      • 
        
    • · key: 用哪个索引做条件定位 (NULL ≠ 没读PK树)
      • 
        
    • · rows: 估算扫描行数 (越少越好)
      • 
        
    • · Extra: Using index=覆盖索引 / Using where=server层过滤
      • 
      
    
    
    
    
    
      
    
        
    
        
    为什么全表扫更快
    
      
    
      
      
        
    • · 顺序 I/O: 100万行 ≈ 1次 page 扫描(磁头不跳转)
      • 
        
    • · 随机 I/O: 1次回表 ≈ 1次 page 随机读(磁头要寻道)
      • 
        
    • · 随机I/O 比 顺序I/O 慢 100~1000倍
      • 
        
    • · 优化器选 I/O 总成本最低的方案,不看索引"好不好用"
      • 
      
    
    
    
    
    
      
    
        
    
        
    实战优化套路
    
      
    
      
      
        
    • · 改 SELECT * 为具体列 → 可能触发覆盖索引
      • 
        
    • · 高频查询列建索引 (选择性 > 5%)
      • 
        
    • · 联合索引按 WHERE 顺序建,让 Extra 出现 Using index
      • 
        
    • · 千万级大表用 LIMIT/分页,别无脑 SELECT *

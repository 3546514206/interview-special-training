Q6 · 为什么 SELECT * 不默认走 PK 索引树

零基础 · 7 帧解答「PK 树就含所有列，为什么不直接走它？」的常见误解

PK 树（行按 PK 排序） name 二级索引 PK 树直接定位（无需回表） PK 树全表扫描（不划算） 关键：PK 树的行是按 PK 排的，不是按 name 排的
逐个扫... 扫 6 行才找到 1 行 = type=ALL 全表扫描 （每行还要 PK 树 → 完整行的回表，但本质是 O(N) 扫描） 所以优化器宁可选「name 索引 + 回表」 ✓ name 树可二分定位 name='张三' 叶子按 name 排 → 二分查找 O(log N) 找到 name='张三' → PK=42 代价：叶子只有 name+PK，必须回表 1 次拿完整行 （1 次随机 I/O 比扫 6 行快得多） 所以优化器选这条路：type=ref + 回表

易错点（面试高频）

  • • ❌「PK 树包含所有列，走它就不回表」→ ✅ PK 树行按 PK 排，WHERE 非 PK 列时帮不上忙
  • • ❌「name 索引走完还要回表，不如直接 PK 全表扫」→ ✅ 1 次 name 二分 + 1 次回表 < 全表扫 N 行
  • • ❌「回表可以避免，只要走 PK」→ ✅ 只有 WHERE/ORDER BY 用 PK 列时才能纯走 PK 树

三种日志层级归属

  • binlog：Server 层，与引擎无关，跨 InnoDB/MyISAM
  • redo log：InnoDB 专属，物理日志，页级偏移
  • undo log：InnoDB 专属，逻辑反向，事务回滚 + MVCC
  • 👉 引擎层两兄弟：redo 保"已提交"、undo 保"可回滚"

为什么必须 2PC？

  • 物理 vs 逻辑：redo 记"哪个页改什么"，binlog 记"哪行怎么变"
  • 粒度不齐：一个 UPDATE 可能跨多个页 + 多行
  • 如果只写一边就 commit → 主从不一致 / 备份不可用
  • 👉 2PC = "两边都 OK 才告诉客户端成功"

ACID 是怎么落的？

  • A 原子性：undo log（未提交 → 回滚）
  • C 一致性：A+I+D 共同保证 + 业务约束
  • I 隔离性：锁 + MVCC（undo log 版本链）
  • D 持久性：redo log + binlog 两阶段提交
  • 👉 三件日志 = 事务机制的物理基础

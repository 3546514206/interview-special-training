📍 在哪里？MySQL 4 层架构中的日志落点（一句话定位）

📋 8 类日志家族每类含：层级 / 格式 / 用途 / 配置 · 标 ★ 的是核心三件套

★ binlog (Server)
Server 层 · 跨引擎
格式：逻辑日志（ROW / STATEMENT / MIXED）
用途：主从同步 · 数据归档 · 误删恢复
何时写：事务 COMMIT 时统一刷盘
📁 mysql-bin.000001 · 无限追加 · mysqlbinlog 解析
★ redo log (InnoDB)
InnoDB 专属 · 物理
格式：物理日志（页号 + 偏移 + 修改）
用途：崩溃恢复 · WAL 机制的核心
何时写：事务执行中持续写 · prepare → commit
📁 ib_logfile0~ib_logfile3 · 默认 48MB × 4 · 循环写
★ undo log (InnoDB)
InnoDB 专属 · 逻辑
格式：逻辑反向日志（INSERT→DEL / UPDATE→反UPDATE）
用途：事务回滚 + MVCC 版本链
何时写：UPDATE / INSERT / DELETE 时 · 事务结束不立刻删
📁 undo tablespace（rollback segment）· innodb_undo_tablespaces
慢查询日志 (Slow Query)
Server 层 · 调试类
格式：每条超过阈值的 SQL · 含执行时间/锁时间/扫行数
用途：定位慢 SQL · 性能优化起点
何时写：执行时间 > long_query_time（默认 10s）
📁 slow.log · slow_query_log=ON · mysqldumpslow 统计
错误日志 (Error Log)
Server 层 · 默认开启
格式：启动 / 运行 / 关闭的所有错误 / 警告 / 信息
用途：故障排查第一站（启动失败、连接异常、崩溃）
何时写：实时 · 几乎所有重要事件
📁 hostname.err（5.7后） · log_error 配置 · ⚠ 不能关闭
通用查询日志 (General)
Server 层 · 调试类 · 默认关闭
格式：每条收到的 SQL · 包含连接/断开
用途：完整审计 / 调试某个应用的 SQL 行为
何时写：开关开启后实时
📁 general.log · general_log=ON · ⚠ 生产慎开（量大）
中继日志 (Relay Log)
Server 层 · 从库专属
格式：从主库拉取的 binlog 副本（同等内容）
用途：从库重放主库操作 · 主从复制的"中转站"
何时写：从库 IO 线程写入后，SQL 线程读出重放
📁 relay-bin.* · relay_log_info_repository=TABLE（多线程安全）
元数据日志 (DDL Log)
Server 层 · 内部使用
格式：DDL 操作的元数据变更记录
用途：保证 DDL 在从库重放时 崩溃安全
何时写：CREATE / ALTER / DROP 等 DDL 时
📁 ddl_log.log · 一般用户不感知 · 内部协调使用
★ 三件套（binlog + redo + undo）是事务持久化与一致性的核心，缺一不可；其余 5 种用于排错（错误 / 慢查询 / 通用）或复制（relay / DDL）。

🎯 用途速查 · 4 个运维场景发生问题时，"我该看哪个 log"

🚨 场景 1 · MySQL 启动失败 / 进程崩溃

Q：实例起不来、连不上、报错
👉 看 error_log · 路径 hostname.err · 第一站
👉 若涉及数据损坏：redo log 状态扫描 + binlog 是否完整

🐢 场景 2 · 系统慢 / 接口超时

Q：业务突然慢、查询跑 30s 才返回
👉 开 slow_query_log=ON · long_query_time=1（生产建议）
👉 用 mysqldumpslow -s t slow.log 按时间排序

📡 场景 3 · 主从同步延迟 / 同步中断

Q：SHOW SLAVE STATUS 报错 / Seconds_Behind_Master 飙高
👉 看从库 relay_log · SHOW SLAVE STATUS 看位置
👉 看主库 binlog 位点 · mysqlbinlog 解析具体 SQL

💀 场景 4 · 误删数据 / 删表 / 删库

Q：DBA 不小心 DROP TABLE 怎么恢复？
👉 看 binlog · 找到 DROP 前的位置
👉 用 mysqlbinlog --start-position 还原到备份 + binlog 重放

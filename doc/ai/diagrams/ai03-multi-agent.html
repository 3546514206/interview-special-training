📋 单 Agent vs 多 Agent：何时用哪个？

决策表

任务简单、可线性完成✓✗多 Agent 增加延迟和成本

💡 通用经验：从单 Agent 起步，工具数 > 10 / prompt > 4K / 需要 guardrail 时再考虑多 Agent。

上下文隔离 vs 共享

  • 共享：所有 Agent 同一上下文（Blackboard 模式），易冲突、token 暴涨
  • 隔离：每 Agent 私有上下文，通过消息总线传递摘要
  • 混合：私有 + 共享黑板（推荐），关键信息广播、敏感信息隔离
  • 隔离代价：需设计序列化协议，否则信息丢失
  • LangGraph 用 StateGraph、CrewAI 用共享 memory、AutoGen 用 GroupChat

冲突解决方案

  • Voting：多 Agent 投票，多数决（适合分类/选择）
  • Critic-Reviewer：一个 Agent 写，一个 Agent 审
  • Debate 辩论：双方各持观点，最后裁决（适合决策类）
  • Priority 优先级：Supervisor 优先级裁决
  • Confidence 加权：用 self-confidence 分数加权
  • 无收敛 → 引入人类或硬阈值兜底

通信协议

  • 消息总线：Kafka / Redis Streams，事件驱动
  • 共享内存：in-memory dict（性能高，难持久化）
  • Blackboard：结构化状态空间，Agent 读写
  • Pub/Sub：发布订阅，Agent 订阅感兴趣的事件
  • Frameworks：LangGraph、CrewAI、AutoGen、MetaGPT、Swarm

评估指标

  • 任务完成率：最终目标达成率（最重要）
  • 单 Agent 失败率：每个 Agent 独立看
  • 通信轮次：越少越高效，过多 → 协调失败
  • Token 成本：多 Agent 通常 3-10× 单 Agent
  • 延迟：串行 vs 并行 Agent 分布
  • 收敛速度：辩论多久达成一致

MySQL 主从复制 · 三线程链路与一致性模式

binlog（8.0 默认 ROW，已核实）→ dump 线程 → IO 线程 → relay log → SQL 线程重放；半同步 AFTER_SYNC 为推荐等待点

GTID

  • server_uuid:transaction_id 全局标识事务
  • 从库自动定位复制位点，failover 无需人工比对文件名与位置
  • 5.7+ 新建集群的默认选择

为什么从库重放慢于主库执行

  • 主库：多事务并发组提交落盘
  • 从库：传统单 SQL 线程串行重放
  • 并行度天然不对称 → WRITESET 并行复制是对症手段

延迟观测与写后读

  • Seconds_Behind_Master 有局限（长事务期间失真）
  • 可靠观测：位点差 / GTID 差 + 心跳表
  • 写后读一致性：强制走主 / 版本检测重读 / GTID 等待（WAIT_FOR_EXECUTED_GTID_SET）

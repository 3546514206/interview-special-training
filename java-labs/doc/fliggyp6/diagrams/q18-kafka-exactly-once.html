Q18 · Kafka 不丢不重复

不丢 = acks=all + min.insync.replicas≥2 + 先处理后提交；不重 = PID/seq 幂等（单分区）+ 事务（跨分区）+ 业务幂等兜底

不丢（两端三处）

  • • 生产：acks=all + retries 大 + 事务
  • • Broker：副本 ≥3 + min.insync.replicas ≥2
  • • 消费：先处理再手动提交 + 关闭前 commitSync

幂等边界（高频追问）

  • • PID+seq：单分区 + 单会话
  • • 重启换 PID → 幂等失效（可实验复现）
  • • 多分区原子 → 事务；in.flight ≤5 的原因

易错点

  • • ❌ min.insync.replicas=1 → 等于没设
  • • ❌ commitAsync 优于 Sync → 场景不同，组合用
  • • ❌ 有事务就不重 → 消费重放仍需业务幂等

Java synchronized 底层 Monitor 机制

对象头 Mark Word 通过重量级锁指针指向堆上的 Monitor（ObjectMonitor）； 锁的竞争、阻塞、等待与唤醒全部发生在 Monitor 内部的 _owner / _EntryList / _WaitSet 三个集合之间。 字段与语义已按 JDK 8 HotSpot 源码（hotspot/src/share/vm/runtime/objectMonitor.hpp）逐条核对。

Monitor 字段速查（JDK 8）

  • _owner：当前持有锁的 Thread*，释放锁时置空
  • _EntryList：阻塞在进入 / 重入上的线程，释放锁时从这里选继任者
  • _WaitSet：调用 wait() 后等待通知的线程
  • _recursions：重入计数，保证同一线程可重复获取同一把锁
  • _count：≈ |_WaitSet| + |_EntryList|，STW 期间防止 Monitor 被回收 / 膨胀
  • _cxq：刚到达、尚未进入 _EntryList 的线程（LL 栈）

wait / notify 语义要点

  • wait() 必须在 synchronized 块内调用，否则抛 IllegalMonitorStateException
  • wait() 会释放锁并把线程置为 WAITING；notify() 不转移锁
  • notify() 只把线程从 _WaitSet 移到 _EntryList，仍需重新竞争锁
  • notifyAll() 唤醒全部等待线程，条件变量场景应优先使用
  • 等待条件要用 while 循环重新检查，防止虚假唤醒
  • wait(0) 表示永久等待；带超时的 wait 必须处理超时分支

面试易错点

  • synchronized 的锁不可中断、无超时，需要这些能力用 ReentrantLock
  • BLOCKED（等 monitor 入口）与 WAITING（wait() 后等通知）是两种线程状态
  • 重入计数在重量级锁下由 Monitor 的 _recursions 维护
  • 释放锁发生在 monitorexit，编译器保证成对出现
  • JDK 15 起偏向锁废弃、JDK 18 移除，本图只描述重量级锁路径
  • JDK 13+ 起 _count 字段有调整，具体差异需核实对应版本源码
